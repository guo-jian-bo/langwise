# image_compress_utils

## 目标

新增一个统一的图片压缩工具 `image_compress_utils.dart`，用于在图片选择、拍照、裁剪完成后、文件返回给调用方之前，对本地图片执行统一压缩。

本次只产出设计与实现提示词，不写实现代码。

## 背景

当前 `lib/utils/image_picker_utils.dart` 中已经完成了“raw 原图层”和“单图成品流程层”的初步收敛，但最终图片压缩仍有以下问题：

1. 压缩逻辑还留在 `image_picker_utils.dart` 内部，没有独立成单一职责工具
2. 当前 `flutter_image_compress` 的 `webp` 在 macOS 不支持，执行时会直接抛异常，而不是稳定返回 `null`
3. 项目已经集成 `ffmpeg_kit_flutter_new`，视频链路也已有成熟实践，图片压缩可以复用相同技术栈，避免继续依赖平台支持不一致的图片插件

因此，本次目标不是继续修补现有 `compressImage(...)`，而是把图片压缩正式下沉为独立工具，并统一改成 FFmpeg 实现。

1. `compressImage(...)`

3. 任何后续需要返回“单图成品”的公共入口

目标行为：

- 原图选择 / 拍照方法仍然只返回原图
- 成品图流程在裁剪完成后，统一调用 `image_compress_utils.dart`
- 调用方无需感知 FFmpeg 细节，仍然只接收 `File?`

## 硬性要求

### 输出格式与尺寸

- 输出格式统一为 `webp`
- 目标宽度固定为 `1080`
- 目标高度按原始宽高比自适应计算
- 不允许拉伸
- 不允许裁剪
- 小于等于 `1080` 宽的图片不放大

### 平台范围

必须支持以下平台：

- iOS
- Android
- macOS
- Windows

### 文件行为

- 输入文件必须是本地文件
- 输出文件写入系统临时目录
- 输出文件名必须带唯一标识，避免覆盖
- 压缩成功后返回新的压缩文件
- 压缩失败时返回 `null`
- 失败时不能伪造成功结果

### 业务行为

- 裁剪后的图片必须只压缩一次
- 压缩工具不负责裁剪
- 压缩工具不负责弹窗、权限、来源选择
- 如果输入文件不存在，直接返回 `null`
- 如果输出文件不存在、大小为 `0`、或路径异常，视为压缩失败

## 推荐实现方向

### 推荐方案

统一采用 `ffmpeg_kit_flutter_new` 完成图片压缩。

原因：

- 当前项目已接入 `ffmpeg_kit_flutter_new`
- `video_compress_utils.dart` 已经有现成的 FFmpegKit 使用方式可参考
- `flutter_image_compress` 在桌面端对 `webp` 支持不稳定，尤其 macOS 会直接抛异常
- FFmpeg 更适合精确控制输出格式、缩放策略和跨平台一致性

### 工具职责边界

`image_compress_utils.dart` 只负责：

1. 校验输入文件
2. 读取原图尺寸
3. 计算目标输出尺寸
4. 调用 FFmpeg 执行压缩
5. 校验输出文件
6. 返回最终压缩文件

不负责：

- 权限处理
- 拍照 / 相册选择
- 裁剪弹窗
- 业务 toast 文案编排

也就是说：

- `image_picker_utils.dart` 负责“取图 -> 裁剪 -> 调压缩工具 -> 返回”
- `image_compress_utils.dart` 负责“输入文件 -> 转码压缩 -> 校验输出 -> 返回”

## 推荐对外能力

建议 `image_compress_utils.dart` 对外只暴露一个主入口，语义类似：

- 压缩单张本地图片并返回压缩后的文件

如果需要扩展参数，也建议围绕单一入口增加可选参数，而不是暴露多个平台分支方法。

## 推荐压缩流程

### 标准流程

1. 校验输入文件存在
2. 读取图片原始宽高
3. 计算输出宽高
4. 生成唯一输出路径
5. 执行 FFmpeg 命令
6. 检查 FFmpeg return code
7. 检查输出文件是否存在且大小正常
8. 返回压缩后的文件

### 尺寸计算规则

如果原图宽度大于 `1080`：

- 输出宽度固定 `1080`
- 输出高度按原始比例缩放

如果原图宽度小于等于 `1080`：

- 不放大
- 保持原始尺寸

如果 FFmpeg 编码要求某些尺寸需要修正：

- 宽高应做最小必要修正
- 修正后仍需保持等比语义

## FFmpeg 实现建议

### 命令目标

需要通过 FFmpeg 实现以下目标：

- 输入一张本地图片
- 输出为单张 `webp`
- 尺寸控制为固定宽 `1080`、高度自适应
- 不放大
- 不裁剪

### 缩放策略

FFmpeg 的缩放表达式必须体现以下规则：

- 当原图宽度大于 `1080` 时，缩放到 `1080`
- 当原图宽度小于等于 `1080` 时，保持原始宽度
- 高度按比例自动计算

如果需要，可通过 `ffprobe` / 既有图片解码库先拿原图尺寸，再在 Dart 侧先算好目标宽高，避免把所有判断都塞进命令表达式里。

### 编码质量

实现时需要允许控制质量，但默认值应稳定。

建议：

- 默认图片质量使用与当前项目一致的 `90`
- 后续如有需要，可开放可选参数

### 输出路径

建议输出路径格式类似：

- 系统临时目录
- 文件名包含时间戳
- 扩展名固定 `.webp`

## 失败处理要求

- FFmpeg 命令执行失败时，返回 `null`
- ReturnCode 非 success 时，返回 `null`
- 输出文件不存在时，返回 `null`
- 输出文件大小为 `0` 时，返回 `null`
- 失败时应记录足够日志，方便排查

注意：

- 不能像当前 `image_picker_utils.dart` 那样只在上层 `catch` 后静默返回 `null`
- 压缩工具内部应尽量提供明确调试信息

## 日志与调试要求

至少记录以下信息：

- 输入文件路径
- 输入文件大小
- 输入图片宽高
- 目标宽高
- 输出文件路径
- 输出文件大小
- FFmpeg 命令或参数摘要
- ReturnCode
- 耗时

日志主要用于排查以下问题：

- 某平台 `webp` 转码失败
- 小图被错误放大
- 高度计算错误导致拉伸
- 输出文件存在但为空
- 某些图片格式无法被 FFmpeg 正确处理

## 与 image_picker_utils 的配合要求

1. 原图层仍然只返回原图
2. 成品图流程必须先裁剪，再压缩
3. 图片压缩只允许走统一工具，不允许多条链路各自再写一套 FFmpeg 命令
4. `image_picker_utils.dart` 中不再直接调用 `flutter_image_compress` 做最终成品压缩

## 验收标准

### 功能验收

- 单图成品流程返回前会完成统一压缩
- 四端都能执行图片压缩
- 输出文件格式为 `webp`
- 输出文件可被项目现有上传和预览逻辑正常使用

### 尺寸验收

- 压缩完成后返回的文件真实存在
- 压缩失败不会静默伪成功
