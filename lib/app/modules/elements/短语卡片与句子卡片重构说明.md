# 短语卡片与句子卡片 UI 重构说明

## 概述

本次重构参照已完成的**单词卡片**重构方案，对**短语卡片**和**句子卡片**进行了 UI 和交互的全面升级。核心思路是将两类卡片的布局统一为「左侧面板 + 右侧内容区 + 右边缘操作栏」三栏结构，同时根据短语和句子各自的特性做了针对性裁剪和适配。

---

### 1.3 与单词卡片的关键差异

#### 发音组件不同
- **单词卡片**：使用 `ElementsPronunciationModuleWidget`，包含**音节划分**（Syllable）和**自然拼读**（Phonics）两个子模式及切换按钮。
- **短语卡片**：使用 `ElementsPhrasePronunciationWidget`，**没有音节划分和自然拼读**，仅显示短语文本（支持卡拉OK高亮）、英/美音切换和播放按钮。

> **原因**：短语是多个词的组合，不适合进行单词级别的音节划分和自然拼读分析。

#### 操作栏（Action Rail）差异

| 操作按钮 | 单词卡片 | 短语卡片 | 说明 |
|---------|----------|----------|------|
| 双语对照 | ✅ | ✅ | 相同 |
| 查看等级 | ✅ | ✅ | 相同 |
| 语法特性 | ✅ | ✅ | 数据驱动显示/禁用 |
| 词根词缀 | ✅ | ✅ | 数据驱动显示/禁用 |
| 来源故事 | ✅ | ✅ | 数据驱动显示/禁用 |
| 记忆提示 | ✅ | ✅ | 数据驱动显示/禁用 |
| 短语习语 | ✅ | ✅ | 数据驱动显示/禁用 |
| **核心组件** | ❌ | ✅ **新增** | 短语专有，展示构成短语的核心词汇 |
| 记单词/记短语 | 记单词 | **记短语** | 文案不同 |

#### 记忆功能差异
- **单词卡片**：记忆功能精确到「释义（semantic）」级别，需要从控制器预加载 `semanticFavoritedStatus`，并通过 `resolveSemanticMemoryCard` 解析出对应的记忆卡片。
- **短语卡片**：记忆功能精确到「词性（POS）」级别，使用 `posData.contentId` 直接构建参数，通过 Widget 本地 `Set<int>` 追踪本次会话中的已记忆状态，无需控制器层面的预加载。

### 1.4 底部导航栏
短语卡片保留了与单词卡片相同的底部导航栏，支持：
- 左侧词性下拉菜单（`PopupMenuButton`）
- 右侧释义标签滚动列表（每个 POS 下的语义标签）

### 2.2 布局结构

```
┌──────────────────────────────────────────────────────────────────┐

├────────────────┬─────────────────────────────────────┬────────── │

│  (640px)       │                                       │ (右边缘) │

└────────────────┴─────────────────────────────────────┴──────────┘
```

### 2.3 与单词卡片的关键差异

#### 无音节划分和自然拼读
- 句子卡片使用 `ElementsSentencePronunciationWidget`（卡拉OK风格，逐词高亮）
- **没有音节划分和自然拼读功能**，因为这些是针对单个词汇的语音分析特性

#### 无词性（POS）概念
- 句子没有词性之分，因此：
  - **无底部导航栏**（无词性下拉菜单、无释义标签组）
  - **无词性 Tab 切换**
  - 右侧内容区直接以 `ListView` 滚动展示所有内容

#### 操作栏（Action Rail）大幅精简

| 操作按钮 | 单词卡片 | 句子卡片 | 说明 |
|---------|----------|----------|------|
| 双语对照 | ✅ | ✅ | 相同 |
| 查看等级 | ✅ | ✅ | 句子等级面板仅显示LSRW进度，无星级（句子数据不包含 cardStar） |
| 语法特性 | ✅ | ❌ | 句子无独立词性语法特性数据 |
| 词根词缀 | ✅ | ❌ | 句子无词素分析 |
| 来源故事 | ✅ | ❌ | 句子无来源故事 |
| 记忆提示 | ✅ | ❌ | 句子无记忆小贴士 |
| 短语习语 | ✅ | ❌ | 句子无关联短语 |
| 核心组件 | ❌（短语有） | ❌ | 不适用 |
| **记句子** | ❌ | ✅ | 句子专有，文案改为「记句子」 |

#### 等级面板差异
- **单词/短语/句子卡片**：均包含星级（`StarRatingWidget` + `cardStar.title`）+ LSRW进度条
- 星级面板采用条件渲染：仅当 `cardStar != null` 时才显示星级区域，对三类卡片保持一致的数据驱动策略

#### 记忆功能差异
- **单词卡片**：记忆精确到 semantic 级别，需要弹窗选择释义
- **短语卡片**：记忆精确到 POS 级别
- **句子卡片**：记忆精确到句子整体，直接使用 `sentencesDetils.contentId` + `semanticId`，通过 Widget 本地 `bool _isFavorited` 追踪状态

#### 内容区结构
句子卡片的右侧内容区（`_buildRightPanel`）以 `ListView` 形式依次展示：
1. **句子释义区域** - 包含难度标签、句子原文、翻译、句子类型标签
2. **结构/句法分析区域** - 包含「结构分析」和「句法分析」两个 Tab，复用原有的 `ElementsStructureWidget` 和 `ElementsSyntacticAnalysisWidget`

## 四、重构设计原则

### 4.1 一致性原则
三类卡片统一采用：
- 左侧 640px 面板（图片 + 发音）
- 右侧弹性面板（核心内容）
- 右边缘操作栏（`Action Rail`，hover 展开/收起，3秒后自动收起）
- 统一的弹窗对话框（`_*DetailsModuleDialog`）

### 4.2 特性裁剪原则
- **不适用的功能直接移除**，不保留禁用状态的占位符
- 短语和句子的发音组件使用专用 Widget，不展示单词独有的音节/自然拼读功能
- 句子卡片操作栏精简为最核心的 3 个操作（双语对照、查看等级、记句子）

### 4.3 数据驱动原则
操作栏按钮的启用/禁用状态完全由后端数据决定：
- `enabled: posData.grammatical?.isNotEmpty ?? false`
- `enabled: posData.morphology != null`
- `enabled: posData.story != null`
- 等
