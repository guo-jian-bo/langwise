## 目标与验收口径

- 在“添加语法”页的右侧“召回结果”区域，补充全局“全选 / 全不选”能力。
- 召回结果按后端返回的 `kind` 分组展示。
- 分组头部展示“类别标题 + 数量”。

## 改动点列表

- `views/manage_unit_grammar_add_view.dart`
  - 右侧召回结果头部增加全局“全选 / 全不选”操作。
  - 召回结果列表改为按 `kind` 分组渲染。
  - 新增分组头部 UI，展示类别标题和该组数量。
- `controllers/manage_unit_grammar_add_controller.dart`
  - 新增召回结果分组方法。
  - 新增召回资产全选、全不选方法。
  - 复用可选资产 key 构建逻辑，保持召回后默认全选行为不变。

## 关键设计与关键决策

- 分组维度直接使用后端原始 `kind`，不额外做二次结构包装。
- “全选”只作用于可追加资产；`alreadyPresent == true` 的资产保持不可勾选，也不参与全选。
- 召回成功后，仍然保持“默认全选所有可追加资产”的现状，避免改变已有操作路径。

## 兼容性影响与注意事项

- 不修改召回接口、追加接口和参数结构。
- 不修改左侧材料选择逻辑。
- 不修改追加按钮可用性判断，只是让勾选来源支持全局批量操作。

## 待确认问题或 TODO

- 当前仅提供全局“全选 / 全不选”；若后续需要每个 `kind` 分组内单独批量操作，可在分组头部继续扩展。
