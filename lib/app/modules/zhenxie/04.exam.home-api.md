# 甄写 · 考点接口 API 文档

> 对应需求文档：[`04.exam.md`](./04.exam.md)
> 对应后端接口：
> - `GET /write/zhenxie/exam/home`
> - `POST /write/zhenxie/exam/compare/{module}`
> - `POST /write/zhenxie/exam/compare/goals/sankey`
> - `GET /write/zhenxie/exam/compare/query/meta/group/list`
> 对应后端实现：`ZhenXieExamController`
> 受众：Flutter App / 前端同学
> 说明：本文档已合并首页与三关对比页接口说明；对比页说明见文末第 12、13 节

---

## 1. 首页接口用途

本章说明的 `GET /write/zhenxie/exam/home` 只负责**考点首页 2x2**的数据，不负责：

- 三关对比页
- 真题列表页
- 真题详情页
- 甄写首页上的“考点入口卡片”

它返回的是当前考段（小升初 / 中考 / 高考）下，考点首页需要的一整屏数据，包含：

- 顶部标题区
- 顶部摘要区
- 底部三关切换条
- 首页四格
  - 考什么文章
  - 考什么主题
  - 考什么能力
  - 走什么阶梯

---

## 2. 请求信息

### 2.1 请求方式

`GET`

### 2.2 请求路径

`/write/zhenxie/exam/home`

### 2.3 请求参数

| 参数名 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---:|---|---|
| `stage` | string | 否 | `xiaoshengchu` | 当前考段。可选值：`xiaoshengchu` / `zhongkao` / `gaokao` |

### 2.4 请求示例

```http
GET /write/zhenxie/exam/home?stage=xiaoshengchu
```

```http
GET /write/zhenxie/exam/home?stage=zhongkao
```

```http
GET /write/zhenxie/exam/home?stage=gaokao
```

---

## 3. 返回总结构

接口返回 `HttpResult<ZhenXieExamHomeDTO>`。

前端真正关心的业务数据在 `data` 里。

```json
{
  "code": 0,
  "msg": "success",
  "data": {
    "stage": "xiaoshengchu",
    "title": [{ "lang": "zh", "text": "考点" }],
    "subTitle": [{ "lang": "zh", "text": "EXAM" }],
    "headline": "按要点完整覆盖信息，最常考 · 7/10 项还在通往高考的能力线上",
    "summary": {},
    "stages": [],
    "blocks": []
  }
}
```

---

## 4. 顶层字段说明

### 4.1 `stage`

当前页对应的考段。

可选值：

- `xiaoshengchu`
- `zhongkao`
- `gaokao`

前端用途：

- 标记当前页面是哪个考段
- 配合底部 tab 做当前选中态
- 点击切段时，带着新的 `stage` 重新请求本接口

---

### 4.2 `title`

页面主标题。

当前固定为：

```json
[{"lang":"zh","text":"考点"}]
```

前端用途：

- 顶部主标题展示

---

### 4.3 `subTitle`

页面英文副标题。

当前固定为：

```json
[{"lang":"zh","text":"EXAM"}]
```

前端用途：

- 顶部英文副标题展示

---

### 4.4 `headline`

当前考段顶栏一句。

取值规则：

1. 优先取 `overall.headlines[stage]`
2. 如果没有，再回退当前考段报告的 `overview`

前端用途：

- 顶部大句子直接展示
- 前端**不要自己拼**

---

### 4.5 `summary`

顶部右侧摘要区数据。

字段如下：

| 字段 | 类型 | 说明 | 前端怎么用 |
|---|---|---|---|
| `levelName` | `LanguageText[]` | 当前关门签，如 `A1 · Movers` | 顶部 meta 第一段 |
| `taskCount` | number | 当前关真题数 | 可展示 `n 道真题` |
| `regionCount` | number | 当前关省市覆盖数 | 可展示 `n 省市` |
| `startYear` | number | 最早年份 | 年份跨度 |
| `endYear` | number | 最晚年份 | 年份跨度 |
| `summaryText` | string | 顶部摘要直出文案 | 建议优先直接渲染 |

推荐前端优先使用：

- `summary.summaryText`

当前返回口径示例：

```json
{
  "levelName": [{ "lang": "zh", "text": "A1 · Movers" }],
  "taskCount": 137,
  "regionCount": 15,
  "startYear": 2024,
  "endYear": 2026,
  "summaryText": "A1 · Movers · 137 道真题 · 15 省市 · 2024–26"
}
```

---

### 4.6 `stages`

底部三关切换条数据。

固定返回三项，顺序固定：

1. `xiaoshengchu`
2. `zhongkao`
3. `gaokao`

每项字段：

| 字段 | 类型 | 说明 | 前端怎么用 |
|---|---|---|---|
| `stage` | string | 考段编码 | 切换接口参数、路由参数 |
| `name` | `LanguageText[]` | 考段名称 | tab 文案 |
| `taskCount` | number | 该考段真题数 | tab 旁注数字 |

说明：

- 当前是否高亮，**后端不再下发 `current`**
- 前端请根据当前页面 `stage` 自己判断高亮态

返回示例：

```json
[
  {
    "stage": "xiaoshengchu",
    "name": [{ "lang": "zh", "text": "小升初" }],
    "taskCount": 137
  },
  {
    "stage": "zhongkao",
    "name": [{ "lang": "zh", "text": "中考" }],
    "taskCount": 109
  },
  {
    "stage": "gaokao",
    "name": [{ "lang": "zh", "text": "高考" }],
    "taskCount": 34
  }
]
```

## 5. `blocks` 四格说明

`blocks` 固定返回四项，顺序固定：

1. `genres`
2. `topics`
3. `goals`
4. `ladder`

前端建议：

- 不要依赖数组位硬编码
- 优先按 `block.code` 分发渲染

每个 block 的公共字段如下：

| 字段 | 类型 | 说明 | 前端怎么用 |
|---|---|---|---|
| `code` | string | 模块编码 | 决定渲染组件类型 |
| `title` | `LanguageText[]` | 模块标题 | 卡片标题 |
| `description` | `LanguageText[]` | 模块结论句 | 标题下方一句话 |
| `summary` | `LanguageText[]` | 模块摘要短句 | 次级摘要 / 角标 |
| `total` | number | 当前模块总题数 | 某些模块可作为分母 |
| `items` | `ItemDTO[]` | 模块榜单数据 | 主体内容 |
| `route` | string | 点整卡后的跳转路由 | 点击整卡跳转 |

其中：

- `goals` 额外有 `legends`、`legendDescription`
- `ladder` 额外有 `coveredCount`、`percent`

---

## 6. 四个 block 分模块口径

## 6.1 `code = genres`

表示“考什么文章”。

### 6.1.1 block 级字段

| 字段 | 说明 |
|---|---|
| `title` | 固定为“考什么文章” |
| `description` | 当前关最常考的文章类型结论句 |
| `summary` | 当前榜首文章的摘要短句 |
| `total` | 当前关总题数 |
| `route` | `/zhenxie/user/exam/{stage}/compare/genres` |

### 6.1.2 `items[]` 字段

| 字段 | 类型 | 说明 | 前端渲染 |
|---|---|---|---|
| `code` | string | `genreNid` | 埋点 / 标识 |
| `name` | `LanguageText[]` | 文类名称 | 图例名称 |
| `count` | number | 该文类题数 | 图例数字 |
| `totalCount` | number | 与 `count` 相同 | 可忽略 |
| `percent` | number | 该文类题数占当前关总题数的比例 | 环图或占比展示 |

说明：

- `genres` 的排序按**当前关题数降序**
- 前端渲染“文章环图”时，建议主要使用：
  - `items[].name`
  - `items[].count`
  - `items[].percent`

---

## 6.2 `code = topics`

表示“考什么主题”。

### 6.2.1 block 级字段

| 字段 | 说明 |
|---|---|
| `title` | 固定为“考什么主题” |
| `description` | 当前关最热内容域结论句 |
| `summary` | 当前榜首主题域摘要短句 |
| `total` | 当前关总题数 |
| `route` | `/zhenxie/user/exam/{stage}/compare/topics` |

### 6.2.2 `items[]` 字段

| 字段 | 类型 | 说明 | 前端渲染 |
|---|---|---|---|
| `code` | string | 主主题所在域 `domainNid` | 埋点 / 标识 |
| `name` | `LanguageText[]` | 域名称 | 图例名称 |
| `count` | number | 该域题数 | 图例数字 |
| `totalCount` | number | 与 `count` 相同 | 可忽略 |
| `percent` | number | 该域题数占当前关总题数的比例 | 环图或占比展示 |

说明：

- `topics` 的排序按**当前关主主题题数降序**
- 前端渲染“主题环图”时，建议主要使用：
  - `items[].name`
  - `items[].count`
  - `items[].percent`

---

## 6.3 `code = goals`

表示“考什么能力”。

这是首页四格里最需要特别注意的一块。

### 6.3.1 block 级字段

| 字段 | 类型 | 说明 | 前端渲染 |
|---|---|---|---|
| `title` | `LanguageText[]` | 固定为“考什么能力” | 模块标题 |
| `description` | `LanguageText[]` | 如“哪项最常考 · 几项在通往高考的线上” | 标题下结论句 |
| `summary` | `LanguageText[]` | 如“按要点完整覆盖信息最常考” | 次级摘要 |
| `legends` | `ZhenXieExamLabelDTO[]` | 底部标签 | 图例标签 |
| `legendDescription` | string | `实段 = 主能力 · 淡段 = 兼考` | 图例解释文案 |
| `total` | number | 当前关总题数 | 总规模参考 |
| `route` | string | `/zhenxie/user/exam/{stage}/compare/goals` | 点整卡跳转 |

### 6.3.2 `legends[]`

当前仅下发两个标签：

```json
[
  { "code": "在通往高考的能力线上", "name": [{ "lang": "zh", "text": "在通往高考的能力线上" }] },
  { "code": "基本功", "name": [{ "lang": "zh", "text": "基本功" }] }
]
```

前端渲染规则：

- 朱色标签：`在通往高考的能力线上`
- 骨色标签：`基本功`

### 6.3.3 `items[]` 字段

| 字段 | 类型 | 说明 | 前端渲染 |
|---|---|---|---|
| `code` | string | `goal.nid` | 能力项唯一标识 |
| `name` | `LanguageText[]` | 能力名 | 左侧名称 |
| `count` | number | 主能力题数 | 实段长度 |
| `secondaryCount` | number | 兼考题数 | 淡段长度 |
| `totalCount` | number | 总题数 = 主能力 + 兼考 | 右侧数字 |

说明：

- `goals.items[]` **当前不下发 `percent`**
- 前端不要再从这里取 `percent`
- 横条长度请基于 `count`、`secondaryCount`、`totalCount` 自己控制
- 右侧大数字请显示 `totalCount`

前端推荐渲染映射：

| UI 部位 | 取值 |
|---|---|
| 左侧能力名 | `item.name` |
| 实段长度 | `item.count` |
| 淡段长度 | `item.secondaryCount` |
| 右侧总数 | `item.totalCount` |

示例：

```json
{
  "code": "xiaoshengchu_g3",
  "name": [{ "lang": "zh", "text": "表达计划与打算" }],
  "count": 15,
  "secondaryCount": 22,
  "totalCount": 37
}
```

这个例子里前端应渲染为：

- 主能力：15
- 兼考：22
- 右侧总数：37

---

## 6.4 `code = ladder`

表示“走什么阶梯”。

### 6.4.1 block 级字段

| 字段 | 类型 | 说明 | 前端渲染 |
|---|---|---|---|
| `title` | `LanguageText[]` | 固定为“走什么阶梯” | 模块标题 |
| `description` | `LanguageText[]` | 如“x% 的真题在写作课里有对应的一关可练，落在 n 个关阶” | 结论句 |
| `summary` | `LanguageText[]` | 如“77% 的真题在写作课里有对应的一关可练” | 次级摘要 |
| `total` | number | 当前关总题数 | 分母 |
| `coveredCount` | number | `coverage != none` 的题数 | 覆盖题数 |
| `percent` | number | `coveredCount / total` | 覆盖率 |
| `route` | string | `/zhenxie/user/exam/{stage}/compare/ladder` | 点整卡跳转 |

### 6.4.2 `items[]` 字段

| 字段 | 类型 | 说明 | 前端渲染 |
|---|---|---|---|
| `code` | string | `stageNid` | 关阶唯一标识 |
| `name` | `LanguageText[]` | 关阶名称 | 封面下方名称 |
| `count` | number | 当前关落在该阶的题数 | 封面下方数字 |
| `cover` | string | 封面资源键 | 可用于资源标识 |
| `coverUrl` | string | 封面直链 | 图片展示主字段 |
| `coverMd5` | string | 封面 md5 | 图片缓存判重 |

说明：

- `ladder.items[]` **不再下发 `totalCount`**
- `ladder.items[]` **不再下发 `percent`**
- 前端这里只需要把它当成“关阶缩略横滚卡片”

前端推荐渲染映射：

| UI 部位 | 取值 |
|---|---|
| 封面图 | `item.coverUrl` |
| 封面图资源键 | `item.cover` |
| 关阶名称 | `item.name` |
| 下方题数 | `item.count` |

## 7. `route` 字段怎么用

每个 block 都会下发自己的 `route`，前端点整卡时可以直接跳：

| block.code | route 示例 |
|---|---|
| `genres` | `/zhenxie/user/exam/xiaoshengchu/compare/genres` |
| `topics` | `/zhenxie/user/exam/xiaoshengchu/compare/topics` |
| `goals` | `/zhenxie/user/exam/xiaoshengchu/compare/goals` |
| `ladder` | `/zhenxie/user/exam/xiaoshengchu/compare/ladder` |

说明：

- route 已经带上当前 `stage`
- 前端点整卡时可直接使用

## 8. 与需求文档的对齐说明

这个接口和 [`04.exam.md`](./04.exam.md) 的对齐关系如下：

| 需求文档位置 | 需求 | 当前接口如何支持 |
|---|---|---|
| §5.1 顶栏一句 | 顶栏一句直接展示 | `headline` |
| §5.1 顶部 meta | 门签 / 真题数 / 省市数 / 年份跨度 | `summary` |
| §5.1 底栏三关切换 | 三关 tab + 各关题数 | `stages` |
| §5.1 ① 考什么文章 | 环图 + 图例 | `blocks[code=genres]` |
| §5.1 ② 考什么主题 | 域环 | `blocks[code=topics]` |
| §5.1 ③ 考什么能力 | 横条（实段/淡段） | `blocks[code=goals]` |
| §5.1 ④ 走什么阶梯 | 关阶缩略横滚 | `blocks[code=ladder]` |

## 9. 前端实现建议

### 9.1 强烈建议按 `block.code` 分发渲染

不要写成：

```ts
blocks[0]
blocks[1]
blocks[2]
blocks[3]
```

建议写成：

```ts
const genresBlock = blocks.find(item => item.code === 'genres')
const topicsBlock = blocks.find(item => item.code === 'topics')
const goalsBlock = blocks.find(item => item.code === 'goals')
const ladderBlock = blocks.find(item => item.code === 'ladder')
```

---

### 9.2 `goals` 不要再依赖 `percent`

当前首页能力横条：

- 主能力长度：`count`
- 兼考长度：`secondaryCount`
- 右侧数字：`totalCount`

后端已不再下发 `goals.items[].percent`。

---

### 9.3 `stages` 不要再依赖 `current`

当前高亮态请前端自己根据当前页面的 `stage` 判断。

例如：

```ts
const isCurrent = tab.stage === data.stage
```

---

### 9.4 `ladder` 图片优先取 `coverUrl`

建议优先展示：

```ts
item.coverUrl
```

`cover` 和 `coverMd5` 更适合作为资源标识和缓存辅助字段。

```json
        "route": "/zhenxie/user/exam/xiaoshengchu/compare/ladder"
      }
    ]
  }
}
```

## 11. 当前接口边界

这个接口只返回首页 2x2。

如果前端需要：

- 三关对比数据
- 某一模块的全量节点
- 真题列表
- 真题详情

请调用其他接口，不要从本接口硬推。

## 12. 三关对比接口补充说明

虽然本文件主讲首页接口，但前端联调时通常会从首页卡片继续跳到三关对比页，所以这里把以下两个接口的渲染口径一并补充说明：

- `POST /write/zhenxie/exam/compare/{module}`
- `POST /write/zhenxie/exam/compare/goals/sankey`

这两类接口都支持同一套筛选请求体：

```json
{
  "filters": [
    { "code": "paperNames", "values": ["新高考全国I卷"] },
    { "code": "regionNids", "values": ["beijing"] }
  ]
}
```

说明：

- `filters` 只负责卷别、地区筛选
- 筛选后前端重新请求接口即可
- 对比页三列始终同时展示，不再根据请求体切换某一个考段

### 12.1 通用对比接口

接口：`POST /write/zhenxie/exam/compare/{module}`

`module` 取值：

- `genres`
- `topics`
- `goals`
- `ladder`

接口返回 `HttpResult<ZhenXieExamCompareDTO>`。

前端可按下面这套固定结构渲染页面骨架：

| 字段 | 前端用途 |
|---|---|
| `title` | 顶部模块标题，如 `考什么主题` |
| `description` | 顶部摘要文案，如 `写自己、写社会、写自然，哪一头最热` |
| `note` | 底部固定说明文案，直接展示 |
| `legends` | 左侧图例或节点说明 |
| `columns` | 三关三列主体数据 |

#### 页面顶部怎么画

- 左上模块标题读取 `title`
- 标题右侧说明读取 `description`
- 三列列头读取 `columns[].name`
- 三列副标题读取 `columns[].summaryText`

前端不要再自己拼：

- `A1 · Movers · 113 道`
- `写自己、写社会、写自然，哪一头最热`

这些都以后端返回直出为准。

#### 三列主体怎么画

`columns` 固定是三项，顺序就是：

1. `xiaoshengchu`
2. `zhongkao`
3. `gaokao`

每列字段含义：

| 字段 | 前端用途 |
|---|---|
| `stage` | 该列所属考段 |
| `name` | 列头名称 |
| `taskCount` | 该列总题数 |
| `summaryText` | 该列顶部摘要文案 |
| `nodes` | 该列可视化节点数据 |

`nodes[]` 当前公共字段：

| 字段 | 前端用途 |
|---|---|
| `code` | 节点唯一编码，用于和 `legends[].code` 关联 |
| `value` | 当前节点在该列的题数 / 主值 |
| `secondaryValue` | 兼值，目前主要给能力模块使用 |
| `percent` | 当前节点在该列占比 |
| `order` | 当前节点纵向位次 |

说明：

- 现在通用 compare 接口里，`nodes` 不再重复返回 `name`
- 如果前端需要节点名称，请用 `node.code === legend.code` 去 `legends[]` 里取

#### 不同 module 的渲染口径

`module = genres`

- 左侧图例读 `legends`
- 每个 legend 是一个家族
- `legend.groupCode` / `legend.groupName` 表示所属文风分组
- 三列节点用 `value` / `percent` 画彩带柱

`module = topics`

- 左侧图例读 `legends`
- 每个 legend 是一个主题域
- 三列节点用 `value` / `percent` 画彩带柱

`module = goals`

- 这个通用接口只适合画简版三列能力对比
- 如果前端要渲染 UI 里的完整桑基图，请不要用这个接口，改用 `POST /write/zhenxie/exam/compare/goals/sankey`

`module = ladder`

- 左侧 / 行头信息仍然走 `legends`
- 每个 legend 对应一个写作课关阶
- `legend.groupCode` / `legend.groupName` 表示这个关阶属于哪个文风
- `legend.cover` / `legend.coverUrl` / `legend.coverMd5` 表示关阶封面
- 三列节点仍然只保留统计值，展示信息请按 `node.code = legend.code` 回查

也就是说，`compare/ladder` 前端如果要画成“章法地图”样式，应这样取数：

- 节点标题：`legend.name`
- 所属文风：`legend.groupName`
- 节点封面：`legend.coverUrl`
- 角标数量：当前列 `node.value`

### 12.2 能力桑基图专用接口

接口：`POST /write/zhenxie/exam/compare/goals/sankey`

接口返回 `HttpResult<ZhenXieExamGoalSankeyDTO>`，专门给 `compare/goals` 页面渲染完整桑基图，不和通用 compare DTO 共用。

推荐前端直接按下面这套结构渲染：

| 字段 | 前端用途 |
|---|---|
| `title` | 顶部标题，如 `考什么能力` |
| `description` | 顶部摘要文案 |
| `note` | 底部右侧说明文案 |
| `legends` | 底部三项图例说明 |
| `columns` | 三关三列节点 |
| `links` | 桑基连线 |

#### 顶部怎么画

- 标题：`title`
- 摘要：`description`
- 三列列头：`columns[].name`
- 三列题数摘要：`columns[].summaryText`

#### 底部图例怎么画

`legends` 当前固定会返回三项：

- `gaokao_anchor`
- `on_line`
- `basic`

可直接平铺显示 `legend.name`。

#### 三列节点怎么画

`columns[].nodes[]` 中：

| 字段 | 前端用途 |
|---|---|
| `code` | 节点唯一编码 |
| `name` | 节点名称 |
| `basic` | 是否是“基本功”合成节点 |
| `members` | 仅 `basic = true` 时展示被合并进去的能力 |
| `goalCodes` | 该节点对应的能力编码集合 |
| `value` | 节点高度依据，表示该关涉及该能力的题数 |
| `primaryValue` | 主能力题数 |
| `order` | 节点纵向位次，越小越靠上 |

渲染建议：

- 节点高按 `value`
- 节点上下顺序按 `order`
- 普通节点显示 `name`
- `basic = true` 时显示“基本功”及 `members`

#### 连线怎么画

`links[]` 每项字段：

| 字段 | 前端用途 |
|---|---|
| `source` | 起点节点编码 |
| `target` | 终点节点编码 |
| `notes` | 连线说明，当前可选用作 hover 文案 |

前端绘制时：

- 用 `source` / `target` 到三列节点里找对应节点
- 按 UI 桑基组件规则连线
- `notes` 不是页面固定文案，没有常驻展示要求；需要 hover 或点击说明时再用

## 13. 前端接入建议

为了避免首页和对比页混用字段，建议前端按下面这套方式接：

1. 首页进入：
   调 `GET /write/zhenxie/exam/home`

2. 点击“考什么文章 / 主题 / 阶梯”：
   调 `POST /write/zhenxie/exam/compare/{module}`

3. 点击“考什么能力”：
   直接调 `POST /write/zhenxie/exam/compare/goals/sankey`

4. 打开筛选面板：
   调 `GET /write/zhenxie/exam/compare/query/meta/group/list`

5. 选择卷别 / 地区后：
   带 `filters` 重新请求对应接口

这样前端就不需要：

- 从首页接口硬推对比页结构
- 用通用 compare DTO 去强行兼容完整能力桑基图
- 在 `compare/ladder` 里自己猜所属文风或自己补封面图
